Integrating with the cNGN API requires three things on every request: a Bearer token for authentication, AES-256-CBC encryption of request bodies, and Ed25519 decryption of response payloads. The official SDKs handle all of that for you, so you can call a typed method and work directly with the decrypted result — no cryptography boilerplate required.

## What the SDKs handle for you

Every official SDK abstracts the following so you never have to implement them manually:

- **Bearer authentication** — attaches your `cngn_test_...` or `cngn_live_...` API key to every request header automatically
- **AES-256-CBC request encryption** — serializes your request body to JSON, encrypts it with your AES key, and sends the `{content, iv}` wire format the API expects
- **Ed25519 / Curve25519 response decryption** — decrypts the encrypted `data` field in every response using your private key and returns a plain object
- **Typed endpoint methods** — one method per API endpoint, with typed parameters and return values matching the [API Reference](/api-reference/introduction)

<Note>
SDKs are **server-side only**. Your API key, AES encryption key, and Ed25519 private key must never appear in client-side JavaScript, mobile app bundles, or any code that ships to end users. Use environment variables or a secrets manager on your backend, and call the cNGN API from there.
</Note>

## Using a language not listed?

If your stack is not covered by one of the four official libraries, you can integrate directly over HTTP. All cNGN endpoints are plain REST — see the [Encryption guide](/guides/encryption) for step-by-step instructions on encrypting request bodies and decrypting responses in any language, and the [API Reference](/api-reference/introduction) for the full endpoint catalogue.
