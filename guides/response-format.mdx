Every response from the cNGN API follows a consistent envelope structure. Learning this structure once means you can handle any endpoint's response predictably, whether it's a successful operation, an error, or a paginated list. The most important thing to understand up front is that the `data` field in a success response is always an encrypted string on the wire — you must decrypt it before you can use it.

## Success envelope

Every successful call returns HTTP `200` with this structure:

```json
{
  "status": 200,
  "message": "Balance fetched successfully",
  "data": "<encrypted base64 payload>"
}
```

<ResponseField name="status" type="number">
  The HTTP status code. Always `200` for successful responses.
</ResponseField>

<ResponseField name="message" type="string">
  A human-readable summary of the result, such as `"Balance fetched successfully"` or `"Withdrawal initiated successfully"`.
</ResponseField>

<ResponseField name="data" type="string">
  The response payload, encrypted to your Ed25519 public key and base64-encoded. Decrypt this field using your Ed25519 private key before reading the contents. See the [Encryption guide](/guides/encryption) for the full decryption implementation.
</ResponseField>

<Note>
  Throughout the API Reference, response examples show the **decrypted** contents of `data` so you can understand the payload shape. On the wire, `data` is always an encrypted base64 string — never plain JSON.
</Note>

## Error envelope

Errors return the HTTP status code and a message. There is no `data` field on error responses:

```json
{
  "status": 400,
  "message": "Invalid api key"
}
```

Permission failures use a slightly different shape where `status` is a boolean rather than a number:

```json
{
  "status": false,
  "message": "Permission denied"
}
```

See the [Error Reference](/guides/errors) for a complete listing of every error message, its cause, and how to resolve it.

## Pagination

List endpoints such as [Get Transactions](/api-reference/get-transactions) return paginated results. After you decrypt the `data` field, the payload contains both the records array and a `pagination` object:

```json
{
  "data": [ ... ],
  "pagination": {
    "count": 42,
    "pages": 5,
    "isLastPage": false,
    "nextPage": 2,
    "previousPage": null
  }
}
```

<ResponseField name="count" type="number">
  The total number of records across all pages.
</ResponseField>

<ResponseField name="pages" type="number">
  The total number of pages available given the requested page size.
</ResponseField>

<ResponseField name="isLastPage" type="boolean">
  `true` when the current page is the final page of results; `false` otherwise.
</ResponseField>

<ResponseField name="nextPage" type="number | null">
  The page number to request for the next page of results, or `null` when you are already on the last page.
</ResponseField>

<ResponseField name="previousPage" type="number | null">
  The page number to request for the previous page of results, or `null` when you are on the first page.
</ResponseField>
